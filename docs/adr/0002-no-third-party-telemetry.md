# ADR 0002：不接第三方可观测性（Sentry 等），错误只留本机

## 背景
工程机制补全清单里包含「接入错误追踪（Sentry 或同类）」。
但本项目是**单机私密应用**：聊天记录、记忆、情感数据全部属于用户隐私，
且用户对此有明确红线（任何数据不离开本机）。

## 决策
不接入任何第三方统计 / 错误上报服务。错误可观测性用以下方式在本机实现：
1. React 错误边界（`src/app/error.tsx`）：页面级出错不白屏，给出重试入口，错误写 console。
2. API 路由返回结构化 JSON 错误（`{ error }`），页面按需 toast。
3. 关键路径 `console.warn/error`（服务端终端可见），配合后台分析状态接口可自查。
4. 运行状态自查：`npm run smoke`（接口冒烟）、`npm run doctor`（环境自检）、设置页「连接自检」。

## 理由
- 隐私优先于可观测性：任何外发通道都可能泄露聊天内容，收益远小于风险。
- 单机单人应用没有「线上排障」需求；用户可看到的现象（白屏 / toast / 终端日志）足够定位。

## 影响
- 发生错误时没有远程聚合视图；依赖用户主动反馈 + 本地日志。
- 未来若出现多设备/多用户需求，需重新评估（新 ADR），并默认匿名化 + 用户显式同意。

## 替代方案
- Sentry 自托管：仍引入重量级服务与运维成本，单机场景不成立。
- 本地日志文件：可作为下一步（当前 console + 终端输出已覆盖）。
